# ESP32-S3 单摄像头预测巡线（第一版）

这个工程在 ESP32-S3 上直接读取 JQ-CAM12 的 MJPEG 图像、识别黑线并控制 TB6612。运行时不需要电脑和 Python。当前参数为 `threshold=110`、`ROI=0.70`、`BASE_PWM=40`，以后以源文件顶部宏定义为准。

## 为什么能处理车底盲区

摄像头看不到车轮脚下约 10 cm 是正常的。程序把可见地面分成远、中、近三段，按 `15% / 25% / 60%` 计算目标方向；近处决定当前偏差，远处提前反映弯道趋势。普通巡线丢线后会持续按最后可靠方向低速行驶，不再进入 `LOST_STOP`；硬件或数据故障仍保留安全停车。

这不是长时间“猜路”。单摄像头没有脚下观测，预测只能跨越很短的盲区；急弯需要降低速度和保持足够宽的黑线。

## 关键安全设置

小组成员首次烧录前，建议先把代码中的设置改为：

```c
#define MOTOR_OUTPUT_ENABLED 0
```

此时摄像头和算法运行，但 STBY 保持关闭，电机不会转。当前仓库为了保留已经验证的实车状态设为 `1`；确认识别方向和电机接线前，不要直接落地运行。

电机映射：A 左前 `11/12/13`，B 后轮 `14/15/16`（巡线保持停止），D 右前 `17/18/21`，STBY `GPIO10`。

霍尔编码器沿用 `.ino` 接线：A轮A/B相为 `GPIO48/47`，D轮A/B相为 `GPIO42/41`。路口方向确认后，程序记录A、D起点；A轮前进增量与D轮取反后的前进增量都达到150，才开始原地转弯。

## 显示屏

屏幕沿用 `v20_line_car_vscode.ino` 的 LQ-TFT18SPIV33/ST7735 接线：

| 屏幕引脚 | ESP32-S3 |
| --- | --- |
| CS | GPIO8 |
| SCK | GPIO9 |
| SDI/MOSI | GPIO1 |
| D/C | GPIO2 |
| RST | GPIO3 |
| VCC、BLK | 3.3V |
| GND | GND |

顶部使用约 `24×24` 点阵大字显示导航过程，方向与 `.ino` 的 `setRotation(1)` 一致。状态依次包括“识别左转/识别右转、丢线直行、开始左转/开始右转、识别新线、直行、停车”；下方三行分别显示 A、B、D 三轮的带符号PWM，负号表示反转。当前摄像头巡线不使用B轮，因此B行应保持 `000`。

## 1. 编译、烧录和串口

在 VS Code 打开“ESP-IDF PowerShell”终端，执行：

```powershell
cd esp32_car_vision
idf.py set-target esp32s3
idf.py build
idf.py -p COM7 flash monitor
```

如果普通 PowerShell 找不到 `idf.py`，先执行：

```powershell
& 'C:\esp\v5.4.4\esp-idf\export.ps1'
```

退出串口监视器：按 `Ctrl+]`。如果 COM7 显示拒绝访问，先关闭其他串口监视器、Arduino IDE 和占用串口的终端，再重试；不要同时开两个 monitor。

## 2. 电机关闭状态下验证识别

将车架垫高或拆下轮胎，摄像头对准实际赛道。串口每 5 帧显示一次：

```text
state=TRACK decode=1 area=... x=N近/M中/F远 raw_err=... ctrl_err=... corr=... pwm=L左/R右 motor=ON
```

其中 `raw_err` 是当前帧原始误差，`ctrl_err` 是滤波后真正用于控制的误差，`pwm=L/R` 是本帧发送给左右电机的目标PWM。没有识别到线时 `raw_err=9999`，普通巡线会进入 `BLIND_HOLD` 或 `LOST_HOLD` 并继续低速行驶。

直角转弯日志还包括：

```text
hint=LEFT scan=... ext=L.../R... turn=LEFT turn_ok=... pwm=L-36/R36
```

- `hint`：当前帧检测到的大块侧向分支方向。
- `scan`：前方扫描区域内、属于主线连通区域的黑色像素数。
- `ext=L/R`：该区域相对近处主线中心向左、向右延伸的像素距离。
- `turn`：已经记住的转弯方向；即使随后丢线也不会丢失。
- `turn_ok`：原地旋转时，新线连续居中的帧数；达到 3 才恢复巡线。

依次做四个测试：

1. 黑线在画面中央：应为 `TRACK`，`error` 接近 0。
2. 黑线移到画面左侧：`error` 应为负数。
3. 黑线移到画面右侧：`error` 应为正数。
4. 挡住或移走黑线：先出现 `BLIND_HOLD`，随后变为 `LOST_HOLD`，并持续按最后可靠方向低速行驶。

`x=近/中/远` 是三个观察区域内的线中心。急弯时三个数通常逐渐错开，这正是前视预测所需的信息。

## 3. 解锁电机并架空测试

上述结果正确后，把 `main/car_vision_main.c` 中 `MOTOR_OUTPUT_ENABLED` 改成 `1`，重新 `build`、`flash monitor`。车轮必须离地：

- 中线：A、D 两轮低速前进，B 不转。
- 线在左边：车辆控制量应向左修正。
- 线在右边：车辆控制量应向右修正。
- 丢线超过 6 帧：所有电机停止。

如果左右修正完全相反，先不要落地测试；这通常是整车左右轮定义或某个电机接线方向与当前映射相反，需要根据架空结果修正。

## 4. 落地低速调试顺序

一次只改一个参数：

1. `BLACK_THRESHOLD`：mask 漏掉黑线就增大；地砖阴影也变黑就减小。先在 120～140 内调整。
2. `MIN_COMPONENT_AREA`：噪声被当成线就增大；远处细线总是 LOST 就减小。
3. `BASE_PWM`：当前为 40。新车首次测试建议从 32 开始；急弯冲出路线时先降速，不要先增加转向增益。
4. `MAX_CORRECTION`：修正不足再小幅增大；左右摆动就减小。
5. `BLIND_HOLD_FRAMES`：只负责跨过车底短盲区。过小会提前停车，过大会在真正丢线后盲走。

建议先测试 1 米直线，再测试大半径弯道，最后才测试急弯。每次记录 `error`、状态和车辆实际方向。任何方向不确定时，立即断开电机电源；固件的 LOST 停车不是机械急停的替代品。

## 5. 直角转弯状态机

流程不是固定时间转弯：

```text
TRACK
  → 连续2帧发现左/右大块侧向连通黑线
PEND_LEFT / PEND_RIGHT
  → 以设定PWM向前行驶，跨过约10cm摄像头盲区
  → A、D轮霍尔编码器前进计数都达到150
TURN_LEFT / TURN_RIGHT
  → 左右轮以-36/+36或+36/-36原地旋转
  → 新线连续3帧位于画面中部
REACQUIRED
  → PWM 30低速接线，然后恢复TRACK
```

若旋转80个已处理帧仍找不到居中的新线，进入 `TURN_FAILED` 并停车。这只是防止无限旋转的安全上限，不是按时间判定转弯成功；复位后才能重新运行。

直角识别相关参数：

- `TURN_SCAN_AREA_MIN`：侧向区域至少有多少黑色像素；误触发就增大，漏检就减小。
- `TURN_SIDE_EXTENT_MIN`：侧向延伸至少多少像素才像直角分支。
- `TURN_SIDE_DOMINANCE`：左、右延伸差至少多大才确定方向。
- `TURN_HINT_CONFIRM_FRAMES`：连续多少帧相同方向才记忆。
- `TURN_APPROACH_PWM`：记住方向后的直行速度。
- `TURN_APPROACH_ENCODER_COUNTS`：开始原地转弯前，A、D轮各自需要达到的前进计数，当前为150。
- `TURN_APPROACH_SAFETY_MS`：编码器断线或车轮卡住时的安全停车上限，只负责报错停车，不用于判定前进完成。
- `TURN_SPIN_PWM`：原地旋转速度，当前为36。
- `TURN_CENTER_TOLERANCE`：新线允许偏离画面中心的范围。
- `TURN_REACQUIRE_CONFIRM_FRAMES`：新线连续居中确认帧数。

首次测试必须架空：用黑胶带摆出左、右直角，依次确认日志出现 `PEND_*`、`TURN_*`、`REACQUIRED`，并检查 `TURN_LEFT` 时PWM为 `L-36/R36`、`TURN_RIGHT` 时为 `L36/R-36`。如果车头实际旋转方向相反，只交换 `get_spin_pwm()` 中左右转的两组符号，不要调整识别方向。

## 当前算法边界

- 只选择与底部观察条相连的最大黑色区域，尽量排除远处横线和家具阴影。
- 连续 3 帧确认后才进入 TRACK。
- 预测来自当前画面的远/中/近几何关系和最后可靠误差，不是机器学习模型。
- 已支持单一左直角或右直角的提前记忆和原地找线。
- 连续转弯时，会在当前原地转弯末段暂存连续出现的相反方向提示，并在 `REACQUIRED` 后启动下一次编码器接近。
- 近、中、远线路中心明显位于同一侧时，方向判断优先采用中心轨迹；方向不明显时才使用左右延伸范围。
- 十字路口、左右同时存在的分叉以及路线选择仍未定义；左右延伸接近时不会给出方向提示。
